# @construkt-kit/docs

MDX docs for Construkt Kit sites. A build step, `construkt-kit-docs`, reads the pages and the typed nav, fails the build on
anything broken, and writes what the site serves: a page manifest, a search index, `llms.txt`, a markdown copy of each
page, and one TanStack route file per page. React components lay the pages out on `@construkt-kit/ui`.

## Setup

```ts
// docs.config.ts, next to package.json
import { defineDocsConfig } from "@construkt-kit/docs/config";

import { docsNav } from "./src/docs/nav.ts";

export default defineDocsConfig({
  roots: [
    { contentDir: "content/docs", base: "/docs", routesDir: "src/routes/docs", nav: docsNav },
  ],
  headModule: "@/docs/head",
  manifestPath: "src/docs/manifest.gen.json",
  searchIndexPath: "/docs/search.json",
  publicDir: "public",
  siteUrl: "https://example.com",
  knownRoutes: ["/", "/pricing"],
  markdown: {
    Shot: (node, { attribute }) => `![${attribute("alt")}](/shots/${attribute("id")}.webp)`,
  },
  watch: ["src/docs/nav.ts"],
});
```

```json
"scripts": {
  "build": "construkt-kit-docs && vite build",
  "dev": "construkt-kit-docs --dev & vite dev"
}
```

```ts
import { rehypePlugins, remarkPlugins } from "@construkt-kit/docs/mdx";
// vite.config.ts: give MDX the heading ids the CLI checks anchors against
import mdx from "@mdx-js/rollup";

plugins: [
  tanstackStart(),
  mdx({ providerImportSource: "@mdx-js/react", remarkPlugins, rehypePlugins }),
  react(),
];
```

```ts
// panda.config.ts
import { docsPreset } from "@construkt-kit/docs/preset";

export default defineConfig({ designSystem: "@construkt-kit/ui", presets: [docsPreset] });
```

Paths in the config resolve against its directory. The CLI loads it with `tsx`, so the config and the nav it imports may
use the site's `tsconfig` paths.

## The nav and the pages

Each root's `nav` is a typed tree of `NavLink` (`href`, `title`, optional `match` and `external`) and `NavBranch`
(`title`, `children`, optional `icon`). Page titles come from the nav: a page body must not start with an h1.

A page's `aliases` frontmatter (a list of words) adds search terms that lead to the page, such as the words readers use
for what the docs call something else.

A page's route is its file path under `contentDir`, prefixed with `base`; `index.mdx` serves its folder. Relative links
resolve as from `<route>/`, matching a router with trailing slashes. `## Heading [#id]` pins a heading's id, so a link
from the app survives a reworded heading.

## What fails the build

- a page the nav doesn't list, or a nav link no page or route serves
- an h1 in a page body, two headings with one id, or frontmatter the `frontmatter` schema rejects
- a link to a page that doesn't exist, or to a `#heading` the page doesn't have. Links under a non-empty `base` are
  always checked; with `knownRoutes` set, every site-internal link is
- an MDX element with no `markdown` lowering, or a `{expression}` other than a comment, since neither has a markdown form
- a page whose URL a hand-written route also serves (a layout above it is fine), or whose file name TanStack reads as
  route syntax (`_draft`, `(group)`, `$id`, `route`, `lazy`), so its route file would serve another URL
- anything a plugin reports through `ctx.error`

On an error nothing is written, so the last good output stays. `--dev` rebuilds on every change to the content, the
config and `watch`, prints errors and keeps watching.

## Output

| File                                  | Holds                                                                                                      |
| ------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `manifestPath`                        | `DocsManifest`: per route, title, description, headings, excerpt, backlinks, last commit date, frontmatter |
| `publicDir` + `searchIndexPath`       | Section-level `DocsSearchDoc`s for `DocsSearch`                                                            |
| `publicDir/llms.txt`, `llms-full.txt` | The page index and every page in one file, linking the markdown copies                                     |
| `publicDir/<route>.md`                | Each page as plain markdown, site links made absolute                                                      |
| `routesDir/<path>.tsx`                | `createFileRoute` rendering the page, with `head: () => pageHead(route)`                                   |

The last commit date needs the full git history; in a shallow clone pages get none and the build warns.

Generated route files start with `// @generated by construkt-kit-docs`; the CLI deletes the ones whose page is gone and
never touches the others. Keep them, the manifest and the public outputs out of git.

## Plugins

A `DocsPlugin` adds a site's own checks: `check(page, tree, ctx)` per page, `finish(ctx)` once, and `text(node)` for
the search text of an element the default would read wrong. `@construkt-kit/docs/config` exports the tree helpers they
need: `findElements`, `literalAttribute`, `integerAttribute`, `objectAttribute`, `hasAttribute`, `textOf`.

## Components

| Component       | Does                                                                                                                                                                                                                    |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `DocsShell`     | Sticky sidebar with the nav and search, the page in `<main>`, an optional aside; below `lg`, search beside a menu drawer holding the nav and `menuLinks`                                                                |
| `DocsSkipLink`  | "Skip to content", hidden until focused; render it first in `<body>`                                                                                                                                                    |
| `NavTree`       | Top-level branches collapse; only the current page's section is open                                                                                                                                                    |
| `DocsArticle`   | Badge, title, description, `toc`, the MDX body as prose, the update date and a footer                                                                                                                                   |
| `DocsToc`       | The page's h2 and h3, marking the one being read; `collapsible` for `DocsArticle`'s `toc` below `xl`                                                                                                                    |
| `DocsPager`     | Previous and next page in nav order, skipping links that leave the nav                                                                                                                                                  |
| `DocsSearch`    | A button opening a search palette (⌘K / Ctrl K); loads the index on first open; each page's matching sections below it in page order; recent searches kept in `localStorage`; `extraDocs`, and `onSearch` for analytics |
| `mdxComponents` | `h2`/`h3` with a copy-link anchor; spread the site's own components over it                                                                                                                                             |

They never import a router: pass `LinkComponent` (renders `href`, navigates client-side) and, to `DocsSearch`,
`navigate`. `DocsShell` renders the page's `<main>`, so the site must not wrap it in another, and moves focus there when
the route changes. Sticky columns sit below `--docs-sticky-top`; a site with a sticky header sets it to the header's
height and gives `body` `height: auto; min-height: 100%`, since the kit's preset sizes `body` to the viewport for app
shells and a sticky header leaves with it.

Prose styles reach the markdown only: they sit in the `base` cascade layer, skip elements with a class, and style only
the body's top-level h2–h4 as page headings, so a component in a page keeps its own look. `--docs-measure` (default
`70ch`) caps the length of text lines.

## Rules for package code

- No Panda build extracts this package's source: style through the `docs*` recipes and the prose rules in `src/preset`,
  never `css()`, `styled`, patterns or style props. The preset must not declare `staticCss`.
- `src/core/**` runs in Node at build time: no React, ui, Panda or browser-only imports.

## Tests

`pnpm test` runs the Node tests in `src/**/*.test.ts`. The stories in `src/react/*.stories.tsx` and the behaviour specs in
`src/react/*.spec.ts` run under `pnpm test:stories`.
